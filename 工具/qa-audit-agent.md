# 剩余单位字段 QA 告警审计

审计范围：`backup/20261016-203204/unit-fields-qa-before.tsv`、`unit-fields-qa-final-mia.tsv`、同目录 `install.log`，以及 `fold-apply.ps1`、`安装.ps1` 和实际参与安装的词典。此次仅新增本报告，没有改动现有脚本或词典。

## 结论

剩余告警不是本次安装新增问题。安装前 QA 有 44,555 条，安装后报告有 3,821 条；将 `File + Field` 作为稳定键比较，安装后 3,821 条全部能在安装前基线中找到，新增键为 0。日志也记录“均已存在于安装前基线”并放行。因此 DLC/模组基线机制有效地避免了把原有内容差异判成安装失败，但同时它只负责放行，不代表已有英文/混杂问题已修复。

安装后告警的样本构成：英文句法 3,061 条（1,048 个不同 Sample），纯英文 647 条（267 个不同 Sample），字面 `\\n` 90 条（45 个不同 Sample），控制字符 20 条（2 个不同 Sample），标签异常 3 条（2 个不同 Sample）。其中字段主要是 `YangsThoughts` 和 `Details`，涉及 3,326 个文件；描述在 chassis 与 mech 文件间重复是主要放大因素。`ENGLISH_SENTENCE` 与 `CONTAMINATED` 不是同一报告的重复分类：当前报告没有 `CONTAMINATED` 状态，但其英文句法样本中能直接看到中英混杂，例如英文句子夹着“中型激光器”“装甲”“XL引擎”。这表明该 QA 文件由另一版分类规则生成，或未被当前 `qa-unit-fields.ps1` 重新生成，验收时应统一使用当前脚本重扫。

## 问题分布与根因

- 英文整段/半翻译是主体。高频路径包括 `Eras\\Jihad3068-3080`、`Eras\\DarkAge3131-`、`Eras\\Republic3081-3130`、`Optionals\\Superheavys`、`Optionals\\AriesInitiative`、`Optionals\\ExperimentalWeapons`、`Optionals\\PirateTech` 和 `Optionals\\RISCtech`。样例显示像 `The 4U variant ...` 的原句还在，但武器术语已被替成中文；也有整段纯英文。说明先前的词片段替换污染已经留在游戏 JSON 中，或整段译文键与当前字段不相同。
- 同义词版本和字段变体使整段键难以命中。报告中可见“中型激光器 / 中型激光s”“XL引擎 / XL引擎”等混合旧译法；某些段落还带 Biome Restrictions、Quirk、HTML 标签、动态尾注，导致它与词典中干净英文整段不完全一致。
- 空白折叠词典存在首条优先缺陷。`fold-apply.ps1` 读取顺序是 `dict-mia-update.tsv`、`dict-all.tsv`、`dict-runtime-combined.tsv`、`dict-unit-llm.tsv`、`dict-piratetech-unit.tsv`。精确键 `$exact` 按质量分更新，但同分时保留首条；折叠键 `$fold` 却仅在尚无该键时写入，后续较新/较好译文不能覆盖首条。因而即使后续词典含更好的空白/换行归一化译文，命中折叠键时仍可能得到旧译文。词典内确有重复键且译文不同：`dict-all.tsv` 有 310 个冲突重复，`dict-runtime-combined.tsv` 有 2 个，`dict-unit-llm.tsv` 有 16 个。精确键质量分可以缓解部分冲突，但折叠键首条逻辑绕过了该质量比较。
- 字面换行不是正常 JSON 转义换行。45 个唯一文本出现字面反斜杠+n（其中 90 个文件字段），如中文段落中的 `\\n\\n<b>...`。`fold-apply.ps1` 的正常 `Esc` 会将真实换行写为 JSON 的 `\\n`，解析后应是实际换行；QA 看到字面 `\\n` 说明输入值里存的是双重/字面转义。`repair-localization-json.ps1` 只处理 Localization JSON 的 `<<NL>` 标记，不覆盖单位描述字段，因此不能修复这些项。
- 20 个控制字符问题归为两个不同文本，集中在 Dark Age 与 Jihad 的 Tortoise II Battle Armor 描述及其 chassis/mech 复制项。样本中的 U+001F 位于句子词语之间，属于字段污染；应从对应干净源文本恢复或在确认仅为分隔符后替换成空格，不能把所有控制字符一概删除，以免破坏结构。
- 3 个标签异常来自 PirateTech Mackie 文本中的 `<3 Nature`。当前 QA 的标签检测把文本中的小于号当作 HTML 开始符，导致正常的贴纸文案被误报；它不应按损坏标签盲目删除或转义而改变玩家可见文案。应在 QA 中识别 `<3` 这种文本，或将该字面小于号写作安全文本形式并验证游戏渲染。

## 可执行的批量修复

1. 固定输入快照。对安装前与安装后文件分别运行仓库当前 `qa-unit-fields.ps1`，保存报告和时间戳；统一按 `File + Field + 当前值` 比对，分类变化时不能只看行数。继续保留“DLC/模组差异不阻断安装”的基线放行，但另设翻译覆盖率报告呈现基线遗留项。
2. 将 3,061 条英文句法及 647 条纯英文记录按解析后的字段值去重，并按 `YangsThoughts`/`Details`、来源模块、英文干净源文本分批。优先通过同相对路径从 `RtlCache\\RtCache` 或 Mod 原始源 JSON 取英文，再合并现有 `dict-unit-llm.tsv`、`dict-piratetech-unit.tsv` 和经过审校的历史整段译文；对没有可靠完整译文的唯一文本做人工/大模型整段翻译。不得以词片段替换代替整段翻译。
3. 译文校验 HTML 标签、占位符、单位型号/武器缩写和段落结构；中英混杂只允许专名、型号和明确保留缩写，禁止保留英文完整句法。按“源文本 + 含 Quirk/尾注变体”分别建键，必要时将动态尾注拆成可独立、安全合并的区段，避免用宽泛前缀错误套译。
4. 修正词典装载策略时，对精确键、折叠键都使用同一质量评估及确定性 tie-break（专用新增词典优先级高于旧通用词典；同优先级冲突输出冲突清单并阻止静默选取）。增加 dry-run 统计：精确命中、折叠命中、前缀命中、片段补译、未命中，以及每种命中的来源词典。安装顺序应保证新增审校译文不会被旧词典回写。
5. 换行与控制字符单独走格式修复：将 QA 的字面 `\\n` 唯一值映射到正确真实换行并 JSON 转义写回；Tortoise II 两种源描述优先恢复干净源文本再汉化。所有改写保留带目录结构的原文件备份，并对变更 JSON 逐个解析验证。
6. 重新安装后做三层验收：JSON 可解析；本次修改字段的占位符/标签/换行结构合法；全量 QA 的新增问题为 0，同时逐项检查所有基线遗留告警是否已按修复批次下降。PirateTech `<3 Nature` 单列为 QA 误报/文本标记验收，不计入损坏标签。

## 限制与待补证

本次报告证明“剩余键均在安装前基线中”，但没有据此断言每个告警都来自哪一条具体词典。需要用当前游戏 JSON 值与 `RtlCache` 原始同路径字段、所有词典精确/折叠键做逐值覆盖审计，才能把每个未命中分为缺译文、键变体、历史污染或源文件本身英文。当前全量 QA 报告的分类与现有 `qa-unit-fields.ps1` 输出状态集合不一致，下一轮应重新生成后再做修复前后比较。
